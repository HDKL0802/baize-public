# 星图整理

笔记多了以后星图会变难用：有的链接指向还不存在的笔记（悬空），有的笔记明明是同一主题却互不相干，
还有的其实是同一件事写了两遍。**整理是"定期做一次"的活，不是每写一篇就折腾一遍。**

## 一、先看清楚现状

- 有哪些笔记：`note`（`{"action":"list","limit":200}`）—— 拿到每篇的 `key`、标题、标签、出链数。
- 标签分布：`note`（`{"action":"tags"}`）。
- 整张星图（点 + 边）：`note`（`{"action":"graph","includeAuto":true}`）。
- 某一篇的关系：`note`（`{"action":"links","key":"…"}`）—— **出链里的悬空项是重点**（指向了还不存在的笔记）。

## 二、三类问题分别怎么治

### 1. 悬空链接（指向不存在的笔记）

两种收场，**先问用户要哪一种**：

- 这些链接本来就是"打算以后写的" → **保留别动**，顺手把标题列出来提醒他。
- 写错了 / 笔记改名了 → 用 `note`（`{"action":"write"}`）把目标笔记补出来；
  或者用 `note`（`{"action":"resolve"}`）重解析一遍，看能不能自动接上。

### 2. 同一主题却互不相连

`note`（`{"action":"autolink","topK":5,"minSim":0.55}`）按**向量语义相似度**自动成边。

- **它会写库**，动手前先确认用户同意。
- `minSim` 别调太低：0.5 以下容易把"都带『项目』俩字"的笔记连成一团，比不连更糟。
- **没配向量通道时它会明确报"没有向量"** —— 这时语义连边做不了，就如实说明，别假装连过。

### 3. 重复笔记（其实是同一件事）

- 先用 `note`（`{"action":"list","query":"…"}`）按关键词找嫌疑对象，**再逐篇 `get` 看正文**才下判断。
- 确实重复 → 保留信息更全的那篇（必要时把另一篇的要点并进去，用 `write` 覆盖那一篇），
  另一篇用 `note_forget` 删掉（**它会连同双向链接一起清掉，并且需要人工审批**）。
- ⚠️ **别只凭标题就删**：同名但不同时期的两篇，很可能正是"改过一版"的价值所在。

## 三、收尾

- 把这次整理写进**同一篇**记录：`note`（`{"action":"write","path":"维护/星图整理记录.md"}`）。
  同一路径是**覆盖更新**，所以别按日期攒文件 —— 只记三件事：改了哪些、删了哪些、
  哪些悬空链接留着等用户决定。
- 想定期做，用 `cron` 挂一条（例如 `{"action":"add","expr":"0 9 * * 1","goal":"整理一次笔记星图，把悬空链接和重复笔记列出来给我确认","autoApprove":false}`）。
  `autoApprove` 保持 `false`：整理会删东西，必须在有人看着的时候做。

## 别做

- **没经用户确认不要 `autolink` / `note_forget`** —— 这两个都会改他的库，而且 `note_forget` 不可逆（走审批）。
- 不要用 `fs_write` 去动记忆库的文件：笔记一律走 `note` 工具，否则链接与向量都不会更新。
