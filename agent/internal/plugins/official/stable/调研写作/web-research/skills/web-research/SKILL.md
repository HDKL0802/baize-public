# 联网调研

把「一个具体问题」变成「一篇带来源的笔记」。

## 前提（先确认，别硬来）

- `web_search` **只认显式配置**的搜索通道（配置里的 `search.provider` = `searxng` 或 `duckduckgo`）。
  **没配就如实说"还没配搜索通道、去哪儿配"**，不要伪造搜索结果，也不要拿记忆里可能过时的知识冒充"查到的"。
- `web_fetch` 抓的是静态 HTML；**内容靠 JS 渲染出来的页面**用 `browser` 的 `open`（它等渲染完再取正文）。

## 步骤

1. **拆问题**：把题目拆成 2–4 个关键词组合。一次查一个组合，别指望一个长句子搜出全部。
2. **搜**：`web_search`（`{"query":"…","limit":8}`）拿到标题 + 链接 + 摘要；先看摘要决定要不要点进去。
3. **抓正文**：
   - 静态页直接 `web_fetch`（`{"url":"…"}`）。
   - 抓回来是空的、或只有导航壳 → 换成 `browser`：`{"action":"open","url":"…"}`，必要时给 `waitFor` 一个 CSS 选择器。
   - **步骤已经确定的一批抓取，一次发出去**省往返：`run_tool_batch` 的 `calls` 里放多个 `web_fetch`。
     它**只允许只读工具**（`web_fetch` / `file_search` / `memory` 查询类都在内），危险工具会被它挡回来。
4. **交叉核对**：同一结论至少两个来源；**互相矛盾就都写出来并标明分歧**，不要挑一个当定论。
5. **落成笔记**：`note`（`{"action":"write","path":"调研/<题目>.md","title":"…","content":"…","tags":["调研"]}`）。
   - 正文里用 `[[其它笔记标题]]` 连到相关笔记 —— 星图会据此连线；之后 `note` 的 `autolink` 还会按语义自动补边。
   - **来源必须写进正文**（链接 + 从它那儿得到的要点）。没有来源的调研等于没做。
   - 模板见本技能 `references/source-note-template.md`。
6. **顺手记住结论**（可选）：值得长期记住的一句话结论，用 `memory` 的 `store`；
   `docKey` 固定的那条是**覆盖更新**（适合"最新结论"），别拿它堆旧账。

## 别做

- 不要把整页 HTML 原文粘进笔记：只留要点与来源。
- 不要用 `fs_write` 往工作目录外写东西；成篇的内容一律走 `note`。
