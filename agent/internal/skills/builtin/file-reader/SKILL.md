# 读文件

## 挑对工具

| 要做什么 | 用什么 |
|---|---|
| 看一个文件的内容 | `fs_read`（默认最多 64KB，超出会标 `truncated`） |
| 看一个目录里有什么 | `fs_list` |
| 找文件、或找"哪一行有这句话" | `file_search`（`name` 搜文件名，`query` 搜内容；**只读**） |
| 跑命令（grep / head / wc 等） | `shell_run`（需要后端开着 `allowShell`） |
| 网页正文 | `web_fetch`；动态页用 `browser` |
| 笔记类内容 | `note`（list / get），别当普通文件读 |

## 约定

- 所有路径都在**工作目录**内；越界会被明确拒绝，不要试图绕。
- `fs_read` 只适合文本文件。
- `file_search` 会自动跳过二进制文件与大文件，并在结果里如实计数（`skippedBinary` / `skippedTooBig`）。

## 两条硬规矩

1. **大文件别硬读**：先用 `file_search` 定位到文件与行号，再 `fs_read` 配合 `maxBytes` 只取需要的部分。
2. **读不到就说读不到**：文件不存在、是二进制、编码乱码、权限不足——如实说清（`fs_read`、`file_search` 都会给出具体原因），**绝不编造文件内容**。编出来的内容比"没找到"有害得多。

## 二进制/Office 文件

图片、压缩包、`.docx/.xlsx/.pptx/.pdf` 这些不是纯文本，直接 `fs_read` 会是乱码。
这类交给「Office 与 PDF」技能处理（那里会先探测环境有没有可用的解析工具）。
