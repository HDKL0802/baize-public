# 造技能

把「已经验证过、以后还会再用」的做法固化下来。技能清单会进系统提示，未来遇到同类任务时被 `skill_load` 取全文。

## 什么时候值得沉淀

值得：
- 反复要用的**流程**（先做什么、再做什么、什么情况停下）
- 一套**检查清单 / 口径 / 判断标准**
- 可复用的**模板**（邮件、报告、代码骨架）

不值得：
- 一次性的数据、临时路径、某个具体的 id
- 密钥、令牌、密码
- 只对当前这一次任务成立的步骤

## 怎么写

1. **先写 description**（最重要）：一句话说清"**什么情况下**用这个技能"。系统提示里只会看到这一句，它决定未来的你能不能把这个技能想起来。写清适用场景与不适用场景。
2. **名字**：`skill_manage` 的 `name` 用小写字母/数字/连字符（ASCII，决定落盘目录）；front-matter 里的 `name` 可以是中文（展示名）。
3. **正文**：只写必要步骤与硬约束，别重复 description。
4. **需要模板/清单/脚本**：写成支持文件（`references/` `templates/` `scripts/` `assets/`），别把长清单塞进正文。
5. **一个技能只干一件事**：三个流程塞一个技能，未来的你很难挑对。

## 用哪个工具

工具 `skill_manage`：

| action | 用途 |
|---|---|
| `create` | 新建技能（要 `content` = SKILL.md 全文） |
| `edit` | 整篇重写 SKILL.md |
| `patch` | 局部替换（要 `old_string` / `new_string`） |
| `write_file` | 写支持文件（要 `file_path` / `file_content`） |
| `remove_file` | 删支持文件 |

删除整个技能用 `skill_delete`（**需要人工审批**）。

`content` 必须带 YAML front-matter：

```yaml
---
name: 展示名（可中文）
description: 什么情况下用这个技能。
---
```

## 发布前自检

站在「**完全看不到这次对话**的未来 agent」的角度通读一遍：

- 照着它，能不能只靠这份技能就做对？
- 里面还有没有"当前这次任务"的痕迹（具体路径、临时 id、某次输出）？
- 判断标准是不是可执行（不是"处理好"这种空话）？
