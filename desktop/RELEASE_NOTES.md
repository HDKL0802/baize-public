# 白泽 0.8.2

> 多生态插件接入：把别的 Agent 生态的插件市场接进白泽（当前支持 DSH 插件市场的索引格式 1）。

## 这一版做了什么

- 新增「生态插件源」能力：白泽能读 DSH 插件市场的索引，把里面的插件按内容形态分类 —— 技能型（带 SKILL.md）与工具型（带 MCP 配置）能转译成白泽插件包；纯 cordis 运行时插件（界面/钩子）只进目录、不假装能装。
- 新增接口：`GET /api/agent/ecology/dsh`（拉目录）、`POST /api/agent/ecology/dsh/sync`（转译成白泽插件包与索引）、`POST /api/agent/ecology/dsh/register`（登记成白泽自己的插件源）。
- 生态插件一律标为社区来源（不替第三方宣称官方）；每条都记来源仓库与许可证；探测不到内容形态时如实说明「现在还说不准」，不与「确认不能装」混为一谈。
- 全程只读第三方公开内容，不执行第三方代码、不自动安装。

# 白泽 0.8.1

> 补丁版本（+0.0.1）。本版只做一件事：把「技能」页的编辑改成**读磁盘上的 SKILL.md 原文**再改，
> 不再用 name / description / 正文重组整篇 —— 原来保存一次就会悄悄丢掉 front-matter 里
> 除 name / description 以外的其它字段（triggers、version、自定义键等）。

## 变更

- 后端新增 `GET /api/agent/skills/raw?name=<技能名>`：返回该技能 SKILL.md 的**磁盘原文**
  （`{name, slug, content, bytes}`）。`name` 既接受目录名（如 `triage`）也接受展示名
  （如「分诊」）；缺参数 400、技能不存在 404、读盘失败 500 —— 都是明确报错，不静默返回空内容。
- 桌面端「技能」页点「编辑」时先拉原文；**读取失败会直接报错并停止编辑**，不再用重组内容
  假装成功。保存时按原文整篇写回，front-matter 原样保留。
- 新增后端测试 `TestSkillRawRead`：造一份带 `triggers` / `version` 字段的 SKILL.md，
  断言原文接口能原样读出这些字段（另覆盖缺参数 400 / 不存在 404）。

## 不含

- 手机端沿用 bz-todo-v0.10.17（versionCode 1017），本版不动手机端。
- 未改：模型通道 / 外部 Agent / 频道 / 插件市场 / 人设 / 备份 / 可观测性 / 文件浏览器 /
  独立知识库 / 内置浏览器 —— 这些在 0.8.0 已接线，本版无改动。

﻿# 白泽 0.8.0

这一版把剩下“后端已就绪、只差界面”的八个模块全部接上，并新增文件浏览器、独立知识库（含知识星图）与内置浏览器控制台。

## 本版变化

### 1. 八个模块接上界面
- **模型通道**：预设、增删改、启停、连通性测试、充值账本；远程地址需显式允许。无“剩余额度”查询接口，界面不编数字。
- **外部 Agent**：增删改、启停、测试、派活与最近调用（进程内，重启清零）。
- **频道**：webhook / onebot / 飞书 / 钉钉 / 元宝 / 微信，按类型显示必填项，测试发送，展示真实入站地址。
- **技能**：列表、新建、编辑、删除。后端没有 SKILL.md 原文读取接口，编辑会重组 front-matter，界面已明确警告。
- **插件市场**：源管理、可用列表、安装/更新/卸载/启停。
- **人设**：总开关、文件启停与顺序、编辑保存、归档、恢复内置。
- **备份**：选范围创建、校验、删除，恢复先强制 dry-run 再二次确认。
- **可观测**：运行统计、分桶图、工具/Provider 排行、日志、健康、活动与 uptime，15 秒自动刷新。

### 2. 文件浏览器
- 本机盘符/目录浏览、面包屑、上一级、文本/图片/PDF 预览、目录内按文件名递归搜索。
- 全部走桌面端 `permGate`，范围由「设置 → 桌面控制」决定；不提供任意路径写/删与“用系统程序打开”。
- 新增有边界的搜索接口：最多 300 条、20000 个条目、8 层，不跟随符号链接。

### 3. 独立知识库（笔记型 + 知识星图）
- 笔记正本是 `vault/` 里的 `.md`，Obsidian 可直接打开；支持 `[[双链]]`、`#标签`、出链/反链、全文搜索、标签筛选。
- 目录分组、预览/源码、编辑/新建/删除、改路径即重命名、重建索引、自动连边、重解悬空。
- 知识星图用新的共用组件 `NoteGraph.vue`（力导向画布与「记忆星图」同源；记忆星图本轮保留原实现，未切换）。
- 「从本机导入」：受权限约束地读取本机 `.md` 目录并导入笔记库，不改原目录。
- 调研说明：`d:\xm\REA-Obsidian` 是 Obsidian 逆向取证工程（解包原厂 bundle + evidence），没有可复用的自有笔记/星图源码，**未改动该项目**；可复用的 Obsidian 兼容实现本来就在白泽 `agent/internal/notebook`。

### 4. 内置浏览器（最新 Chromium 内核）
- 内核选型：**WebView2 Evergreen**（与系统 Edge 同源），不打包、不冻结版本；由 Microsoft Edge Update 维护。
- 新增内核信息接口与「内置浏览器」页：显示实际版本、更新渠道、安装位置，并与 Edge 稳定版对比；明显落后时如实提示。
- 控制开关分两级（允许控制浏览器 / 允许 Chrome 扩展），可打开、移交人工、收回、关闭，查看当前 URL/标题/readyState。
- 实测本机 WebView2 `155.0.4283.62` 可启动，页面桥 `status` 正常。
- 离线退化：没装运行时且无网时直接报错，不静默下载；离线装机需预置 Evergreen 安装器或固定版本运行时目录。**断网自动更新未验证**。

### 5. 版本号
桌面端与后端统一升到 **0.8.0**（次版本 +1）。手机端沿用 bz-todo-v0.10.17（versionCode 1017）。

## 安装 / 升级

1. 新装：下载 baize-desktop-setup-0.8.0.exe（用户级安装，不需管理员）。
2. 已装旧版：桌面端「设置 → 桌面端更新」检查并安装；也可直接运行新安装包覆盖。
3. NAS 升级：baize-nas deploy，或设置页里点「更新后端」（只换二进制）。

# 白泽 0.7.3

这一版只做四件事：把已经做过的功能真正接上界面、把更新功能从"依赖后端"里解耦、删掉没用的左上角图标，并给出 SteamCommunity 302 的接入结论（不内置）。

## 本版变化

### 1. 四个"做过但挂着占位"的页面真正接线
- **MCP 服务**：不再是"规划中"。接后端 `/api/agent/mcp`，支持列表与连接状态、新增/编辑（stdio 与 http）、重连、启用/禁用、删除、工具列表与"试调用"。
- **活动追踪**：接 `/api/agent/activity`，显示当前阶段（思考/调工具/审批/压缩/完成）与最近轨迹，3 秒轮询；状态为进程内，重启即清空。
- **账号与共享**：接多用户登录、`/api/agent/users`、`/api/agent/groups*` 与组内共享文档上传/下载/删除；同名多版会自动进入冲突协商。
- **冲突协商**：接组内冲突列表与详情，左右对照两版、在线预览文本/图片、会话内沟通、定稿保留一版或放弃自己那版。
- **记忆星图**：核实后确认早就接线（`MemoryView.vue` + `/api/agent/memory*`），本次未改动。

### 2. 占位页不再糊弄
- 所有剩余占位统一改成诚实状态：后端已就绪但界面未接（providers/external/channels/skills/plugins/persona/backup/observe），或确实尚未实现（files/browser/kb）。未做的不会显示"已完成"。

### 3. 更新不再受后端连接影响

- 后端连不上时这条链路仍完整可用；同时保留手动从 Releases 下载覆盖安装的离线路径。

### 4. 左上角图标删除
- 删除侧边栏左上角装饰性的白泽线描图标（`App.vue` 的 `.bz-mark` 及其样式），保留「白泽 / 个人智能体」品牌文字，导航与骨架布局不变。

### 5. SteamCommunity 302 v2 调研结论（不内置）
- 官方来源为作者羽翼城（Dogfight360）博客；未找到可核实的官方源码仓库，许可证无法核实，因此不允许再分发。
- Linux 版以 AppImage 分发，安装/启动服务需要 root，默认监听 80/443，需系统级 CA 信任，另有 drivers/hosts 模式；与白泽后端的无特权、单端口形态冲突。
- 结论：**不能整建制内置**；详见 `docs/接入调研-SteamCommunity302-V2.md`。

### 6. 版本号
桌面端与后端统一升到 0.7.3（补丁位 +1）。手机端沿用 bz-todo-v0.10.17（versionCode 1017）。

# 白泽 0.7.2

这一版把桌面端「定时任务」从**占位页**做成**真能用的页面**，并补上「立刻跑一次」能力。

## 本版变化

### 1. 定时任务页（桌面端）正式可用
- 之前「定时任务」是「模块规划中」占位（后端接口其实早已就绪），现在接上了真实列表与增删改：
  - 列表展示：表达式、人话描述（如「每天 08:00」「每 30 分钟」）、要干什么、下次触发时间、状态、上次结果/错误、累计运行次数。
  - 新增 / 编辑：写 cron 表达式（含常用预设：每天 08:00、20:00、工作日 09:00、每周一 09:00、每小时、每 30 分钟），填「要干什么」目标；表达式写错会**当场报错并说明原因**，不会留一条「看着加上其实永不跑」的幽灵任务。
  - 启用 / 停用 / 删除（删除带二次确认）。
- 设计沿用桌面端「墨玉·东方蓝图」风格（深色、玉色高亮、状态点），与「任务与审批」列表页一致。

### 2. 新增「立刻跑一次」按钮（后端 + 前端）
- 后端新增 POST /api/agent/cron/run（找不到任务=404，找不到目标/已在跑=409），用与排期**完全相同**的语义当场触发这条定时任务，不等排期。
- 这是这条页面最要紧的按钮：**表达式或目标写错时，用户本来要等到「该跑的那一刻」才发现**；现在加完点一下就能验证能不能跑通。
- 运行状态精确绑定到任务 id（不按目标文本认），两条任务写一样的目标也不会错标「执行中」。
- 调度器在新增/修改后**立即重排一次**（最多 20 秒的 tick 之外立刻生效），列表立刻回的是「最终态」而非空壳。

### 3. 版本号
桌面端与后端统一升到 0.7.2（后端由 CI 用 -ldflags -X main.version=<版本> 注入）；官网下载菜单版本号跟着 Release 走。手机端仍走自己的版本线（bz-todo-v0.10.17，versionCode 1017）。

## 安装 / 升级

1. 新装：下载 baize-desktop-setup-0.7.2.exe（用户级安装，不需管理员）。
2. 已装旧版：桌面端「设置 → 关于」点检查更新即可自动升级；也可直接运行新安包，沿用原安装目录。
3. NAS 升级：baize-nas deploy，或设置页里点「更新后端」（更快，只换二进制）；也可重跑 curl -fsSL https://baize.wydhd.fun/nas/install.sh | sudo bash。

# 白泽 0.7.1

这一版解决两件事：**国内能下、国外能下**，以及**不用重装就能换后端**。

**0.7.0 的修正**：上一版把 Gitee 仓写成了不存在的 `szk0037`，国内那半边等于没用。
本版全部改成真实账号 `HDKL0037/baize-public`（工作仓 `HDKL0037/baize`），
桌面端检查更新、后端「更新后端」、NAS 一键脚本才真正能走国内源。

## 本版变化

### 1. 双源发布：国内 Gitee / 国外 GitHub

- 发布源拆成两个镜像：国内 `gitee.com/HDKL0037/baize-public`，国外
  `github.com/HDKL0802/baize-public`，两个仓内容与 Release 资产完全一致。
- 官网下载菜单会自动探测 GitHub 可达性（2.5 秒超时），不通就走 Gitee；
  菜单底部还留了「下载源：自动 / 国内 Gitee / 国外 GitHub」的手动切换，
  选择记在本地，下次打开还是它。
- 官网与文档里的仓库地址、Releases、文档原文链接都按镜像切换：
  国外点进去是 GitHub，国内点进去是 Gitee。
- 桌面端检查更新不再只认 GitHub：清单依次从 GitHub → Gitee → 本地后端取，
  哪条通走哪条，国内网络不会卡在「检查更新失败」。
- NAS 一键脚本同样双源：哪边快用哪边，也可以 `BAIZE_MIRROR=gitee` 固定。

### 2. 设置页新增「更新后端」

桌面端与手机端的设置页都多了一张「后端更新」卡片：

- 显示当前后端版本、发布源最新版本、正在使用的下载源；
- 「检查更新」只比对版本，不动文件；
- 「更新后端」让后端自己从发布源下载新二进制、sha256 校验、落到
  `<dataDir>/bin/baize-backend.new`，容器重启时自动替换并接管，
  不需要 Docker socket、不需要 SSH、不用重新部署整套服务。
- 非容器（本机直接跑二进制）的情况下只下载不重启，会提示落盘路径，
  由你重启后端后生效。

### 3. NAS 部署与更新更顺

- `install.sh` 的 `deploy` 现在按镜像自动挑下载地址，带 sha256 校验失败即中止。
- 容器内新增 `BAIZE_IN_CONTAINER=1` 与 `entrypoint.sh`：
  启动时若发现 `baize-backend.new`，先提升为正式二进制再启动，
  配合 compose 的 `restart: unless-stopped` 实现「点一下按钮就换后端」。
- `baize-nas` 的 `status / logs -f / rollback / uninstall` 保持原样，
  取消部署仍然要显式加 `--yes`。

### 4. 版本号

桌面端与后端统一到 0.7.1（后端由 CI 用 `-ldflags -X main.version=<版本>` 注入），
官网下载菜单里的版本号跟着 Release 走。
手机端仍走自己的版本线（`bz-todo-v0.10.17`，`versionCode 1017`）——
Android 不允许版本号往回退，旧的 0.10.16 只能往上升级；
手机端设置页也一并加上「更新后端」卡片，连同这版一起装。

## 安装 / 升级

1. 新装：下载 `baize-desktop-setup-0.7.1.exe`（用户级安装，不需要管理员）。
2. 已装旧版：桌面端「设置 → 关于」点检查更新即可自动升级；
   也可以直接运行新安装包，会沿用原安装目录。
3. NAS 升级：`baize-nas deploy`，或设置页里点「更新后端」（更快，只换二进制）；
   也可以重跑一遍 `curl -fsSL https://baize.wydhd.fun/nas/install.sh | sudo bash`。
