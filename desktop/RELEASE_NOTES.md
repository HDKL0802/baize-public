# 白泽桌面端 0.5.24

悬浮球长出「电话」：**两人通话浮窗**（组内像微信一样互发消息 + WebRTC 音视频）与 **「回复AI」**
（文档分叉协商时，双方各点一次确认，AI 自动通读全部记录、判定并合并文档）。

## 本版变化

- **两人通话浮窗**（悬浮球右键 → 两人通话，或 `Alt+Shift+V`；也可从「账号与共享 → 通话」页签发起）：
  - 选对象：我的用户组 → 组内成员，一点就开通话；进行中的通话列在最上面（「继续」）。
  - 通话中：**文字消息**（2 秒轮询增量）+ **发起音视频**（WebRTC，信令走后端中转、媒体 P2P 直连；
    静音 / 关摄像 / 断开）+ **挂断**（挂断后消息仍留在通话里可回看）。
  - 没登录的通话窗（快捷键直接开的）：窗口里给一个**迷你登录**（登录态存在该窗口自己的目录里，
    下次不重登；从主窗口发起的会把主窗口的登录态递进来）。
- **冲突协商接上通话**：「冲突协商」详情页新增 **「发起通话」**（开一条挂在这次协商下的通话）
  与 **「回复AI」** 按钮：
  - 「回复AI」**双方各点一次**才触发（单人点了会如实提示「还差 N 方」）；
  - 触发后后端把「几版同名文档 + 协商聊天 + 通话里的文字留言」交给**第一条可用模型通道**判定：
    **保留某一版** 或 **合并成一份**（合并稿存成组内新正本、清掉其余版本、定稿），
    结果写回协商记录与通话窗（成功 / 失败都有系统留言，绝不静默）。
- **全局快捷键 5 个**（多了 `Alt+Shift+V` 两人通话）+ 悬浮球右键菜单多了「两人通话」。
- 后端新增**两人通话**接口（组内，成员校验 + 非参与人 404）：
  `POST/GET /api/agent/groups/{id}/calls`（开 / 列）、`GET .../calls/{cid}`（详情 + 留言 / 信令增量）、
  `POST .../calls/{cid}/{messages,signal,end}`、`GET .../calls/{cid}/signal`；
  协商加 `POST /api/agent/groups/{id}/conflicts/{sid}/ai-confirm`（确认闸）。

## 验证

- 后端 / 桌面端各自 `go build` / `go vet` / **`go test -count=1` 全绿**（calls 包 3 组用例 +
  协商确认闸与老库迁移 + 判定契约解析 + 端点全链路用例）。
- **真流程冒烟（本地后端 + 假模型通道）**：两用户一组、同名两版文档自动开协商 → 开通话并挂上
  协商 → 双方留言 → 双方 ai-confirm（第一个还差 1 方、第二个触发）→ AI 判定回 `merge` →
  合并稿落库成正本、旧版本被清（`forked=false` 只剩 1 版）、协商 `resolved`、协商记录里留下
  一条「白泽AI：几版已合并成新正本…」系统留言。
- **浮窗真进程冒烟**：起 `desktop.exe -float=call`，`/api/local/float/mode` 回
  `{"mode":"call","title":"白泽 · 两人通话"}`；`/api/local/float/ctx` GET/POST（主进程把
  「该打开哪条通话 + 登录态」递进来）正常；`/float/open` 对 `../../evil` 依旧白名单拒绝。
- 界面 8 个脚本 + `float.html` 内联脚本无头解析全 OK。

## 兼容与说明

- 后端同期升到 **0.9.33**（新增两人通话与「回复AI」判定 / 合并）。手机端 **0.10.16 未改动**
  （通话浮窗是桌面端专属；手机上的冲突协商页暂不挂通话入口，仍可用文字聊天）。
- 「回复AI」依赖**至少一条可用的模型通道**；没配时判定如实回「失败」并写明原因（可在「模型通道」
  配好后重新点「回复AI」重触发）。
- 音视频是**同内网 P2P**（不引 STUN / TURN，跨公网打不通——与冲突页音视频同一口径）。

## 安装

1. 下载并运行 `baize-desktop-setup-0.5.24.exe`（用户级安装，不需要管理员）。
2. 已装过旧版：直接运行即可 —— 会自动认出来并按更新走，**安装位置可改**。
