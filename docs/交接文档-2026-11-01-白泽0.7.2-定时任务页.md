## 二、页面长什么样（做什么用的）

「定时任务」= 到点让白泽自动干一件事。

- **列表**：表达式（附人话说明）、要干什么、下次触发时间、状态（上次失败/执行中/启用中/已停用/表达式不合法）、上次结果与错误、累计运行次数。
- **新增/编辑**：cron 表达式 + 常用预设（每天 08:00、20:00、工作日 09:00、每周一 09:00、每小时、每 30 分钟）+ 「要干什么」目标 + 配方（一般留空）。
- **启用/停用/删除**：删除有二次确认。
- **立刻跑**：不等排期，当场用与排期**完全相同**的语义触发这条任务。

**为什么必须有「立刻跑」**：表达式或目标写错时，用户本来要等到「该跑的那一刻」才发现。加完点一下就能当场验证能不能跑通 —— 这条是按用户「讨厌看起来能用其实不能用」的偏好做的。

## 四、踩坑 / 注意事项

1. **`sc.parsed` 只有 tick 才填** —— 新加的任务在 20 秒内 `exprText` 是空的，看起来像「加了没排上」。解法：`ScheduleNow()` 在 add/update 后立刻用同一把锁、同一套 `schedule()` 排一次，语义与 tick 完全一致。
2. **不能用目标文本标记「正在跑」** —— 两条任务写一样的目标是常事，会双双显示「执行中」，用户分不清。改为记 `curCronID`。
3. **HTTP 状态码不能靠匹配错误文本** —— 原来用 `strings.Contains(err, "没有这个定时任务")` 判断 404，现改为哨兵错误 `errors.Is`。
4. **本机 8899 端口不可用**（`bind: An attempt was made to access a socket in a way forbidden by its access permissions`，Windows 保留端口），验证改用 18099。
5. **PowerShell 5.1 传中文 body 会变问号**（`ConvertTo-Json` + `Invoke-RestMethod` 编码问题），验证时改用 `curl.exe --data-binary @utf8文件`；中文乱码是客户端问题，不是服务端问题。
6. **`Invoke-WebRequest` 在非交互模式下报错**（朗读/提示功能不可用），验证改用 `curl.exe` 或 `Invoke-RestMethod`。
7. **已知历史失败（与本次无关）**：`agent/internal/httpapi` 的 `TestCreateTaskValidation/未知动作` 期望 400 实际 200。已用 `git stash` 在干净树上复现确认为**改动前就存在**，本次未修。
8. **前端验证不动用户真实配置**：桌面端配置在 `%APPDATA%\白泽\desktop.json`，指向 NAS 后端。为了不覆盖它，验证用了一个临时 Node 静态服务器（serve `webui/dist` + 把 `/api/be/*` 代理到隔离后端），没有启动真实桌面端。临时脚本在 `%TEMP%\bz-verify-server.js`，用完可删。
