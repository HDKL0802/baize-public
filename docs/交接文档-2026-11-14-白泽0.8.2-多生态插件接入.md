## 二、为什么不能「直接装」DSH 插件（关键设计前提）

- DSH 插件是 **cordis 运行时插件**：`peerDependencies` 要求 `@deepseek-ai/cordis ^4.0.1`，靠 fiber 挂载到宿主。**白泽没有 cordis 宿主**，把 DSH 的 bundle 原样塞进白泽不会运行。
- 所以本设计是**两层**，而不是「假装都能装」：
  1. **目录层**：白泽直接读 DSH 格式 1 索引，把每个插件摆上货架；生态插件一律 `channel=community`（**不替第三方宣称官方**）。
  2. **转译层**：只把「白泽真能用的内容」转成白泽插件包，装不了的明确写原因。

### 四类判定（Kind）

| 判定 | 依据 | 处理 |
|---|---|---|
| `skill` | 仓库里有 `SKILL.md` | 转成白泽技能（包内 `skills/<slug>/SKILL.md`） |
| `tool` | 有 `mcp.json` / `.mcp.json` | 转成白泽插件的 `mcp[]`（stdio/http 映射） |
| `runtime` | 依赖 `@deepseek-ai/cordis` / `dsh-client-runtime` | **仅目录**，文案写明「这是 cordis 运行时插件（界面/钩子），白泽没有 cordis 宿主，装了不会运行；这里只作目录展示」 |
| `unknown` | 探测不出 | **仅目录**，文案写明「没能探测到内容形态…这不代表它一定装不了 —— 只是现在还说不准」（**与「确认不支持」严格区分**） |

- 精确安装性：`Installable = Kind == skill || Kind == tool`。

## 三、DSH 格式 1 索引（参考实现开源可读）

- 位置：`D:/DeepSeek haress/resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-plugin-market/`（市场服务）+ `dsh-plugin-market-index/`（格式 1 校验器与类型）+ `dsh-plugin-manager/` + `dsh-host-plugin-inventory/`。
- 顶层：`{format:1, title, description?, metadata:{categories,labels,sortKeys}, plugins:[...]}`。
- 插件：`{name, title?, description?, icon?, author?, homepage?, repository?, metadata:{category?,keywords,labels,sortKeys}, versions:[...]}`。
- 版本：`{version, publishTimestamp, source:{npm(可带 registry) | git(url + 40位小写 commit + 可选 path)}, engines:{dsh?}}`。
- `title`/`description` 是本地化文本（字符串或语言对象）→ 白泽侧用 `localizedText` + 自定义 `UnmarshalJSON` 解析。

## 四、协议对照与转换产物

### 白泽原生协议（agent/internal/plugins/）
- 源：`Source{Name, URL, Enabled}`；URL 指向 `index.json` 或本地路径。
- 索引：`Index{Schema, Name, Updated, Plugins []Meta}`；`Meta` 含 id/name/version/description/author/homepage/license/tags/minBaize/channel/stage/category/url/sha256/size；`url` 相对 `index.json`；`sha256` 校验。
- 远端源目录规范：`official/<stable|beta>/<分类>/<插件id>/plugin.json`。
- 插件包：zip，根目录 `plugin.json`（schema/id/name/version/description/…/mcp[]），技能在 `skills/<slug>/SKILL.md` **自动发现**；`mcp[]` 用 `mcp.ServerConfig`。
- 内置源 `builtin:official` 随后端二进制分发（go:embed），离线可用。

### 转换产物（不破坏原生协议）
- `Build` 生成 **普通白泽源**：`<out>/index.json` + `<out>/packages/*.zip` → 可直接挂进 `config.PluginSources`，原生市场逻辑零改动。
- 生态 ID 归一：`@weibaohui/dsh-fireworks` → `weibaohui.dsh-fireworks`（白泽 ID 规则：小写字母数字开头，可含 `-` `_` `.`，≤64 字符）。

## 五、三个后端接口

- `GET /api/agent/ecology/dsh?index=<URL或本机路径>&probe=0` → 返回目录，每条带 `kind` / `installable` / `reason`；`probe=0` 为快速纯目录模式（默认逐条联网探测）。
- `POST /api/agent/ecology/dsh/sync` → body `{index,name,probe,maxEntries}`；产物 `<dataDir>/ecology/<name>/index.json` 与 `packages/*.zip`；响应含 `outDir`/`indexPath`/`built`/`skipped`/`packages`/`errors`。
- `POST /api/agent/ecology/dsh/register` → body `{name,url}`；写入 `config.PluginSources`（同名更新、否则追加，`Enabled: true`）。

## 八、打包踩坑（复用省时间）

- PowerShell / pwsh **不在 PATH** → `build.ps1` 不能直接跑，用 cmd.exe 手工走等价步骤（npm run build ×2 + go build ×2 + 复制 dist→bin + zip + NSIS）。
- NSIS：`makensis` 遇中文路径乱码 → 把 `installer.nsi` **复制到纯 ASCII 目录**（如 `C:/bz082work`）再编译，`${__FILEDIR__}` 才会指向正确位置；工作目录需平铺 `baize-desktop.exe` + `ui/` + `float/dist/` + `browser-ext/` + `icon.ico`（图标默认 `${__FILEDIR__}\icon.ico`，真实文件在 `desktop/assets/icon.ico`，要复制到工作目录根）。
- Go 注释里出现成对引号（如 `"http://"`）会让词法分析器把后续行当字符串续行 → **注释里别写 URL**。
