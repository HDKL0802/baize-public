## 一、主帖：五层记忆系统（华生忆梦）

### 核心主张

> 「别让 AI 记住一切，让它找得到一切。」
>
> 上下文是**工作台**，不是抽屉。抽屉要分层、要贴标签、要能搜。工作台上只放这次要用的东西。

### 问题诊断

| 做法 | 为什么错 |
|------|----------|
| 上下文压缩摘要 | 「知道」但不「记得」—— 摘要丢了语气和细节，亲密感消失 |
| 不压缩硬塞爆 | token 爆炸、硬上限断片、越长越抓不住重点 |
| 全量长期记忆文档注入 | token 翻几倍、缓存永远命中不了（前缀每次变）、像翻字典抓不住当下重点 |

**共通错误**：都想把「记忆」放进「上下文」里。

### 五层结构

```
┌─────────────────────────────────────────────┐
│  第1层 工作台（上下文）                       │
│  只放本次对话最近几十条消息 + 角色设定        │
├─────────────────────────────────────────────┤
│  第2层 随身小本子（滚动窗口）                 │
│  最近200条消息，随对话滚动，易失（接得上话）   │
├─────────────────────────────────────────────┤
│  第3层 档案柜（核心）★                        │
│  每天定时归档 → 目录+事件全量存储              │
│  memory/YYYY/MM/DD/ 一件事一个文件            │
├─────────────────────────────────────────────┤
│  第4层 她自己的东西                           │
│  人设卡（管理员写）+ 她自己那份人设 + 日记    │
│  + 相册 + 对每个人的印象                     │
│  ⚠️ 必须和「事实记忆」分开，否则性格漂移      │
├─────────────────────────────────────────────┤
│  第5层 原始录像（永不删）                     │
│  每一轮 + 每个工具调用 + token 用量原样存     │
│  平时不读，查不到/复盘时才翻                  │
└─────────────────────────────────────────────┘
```

### 第3层档案柜设计（核心巧思）

**目录先行，按需回放**（不是塞进 prompt）

```yaml
# memory/2026/10/17/_index.md
# 当天目录：
# - [01] 改不了头像和空间 — 想让她换头像改昵称，她当时没权限只能拒绝。
#   标签: 权限,头像
#   来源: 私聊
# - [02] 清点自己能干啥 — 被问现在能做什么，她报了一遍技能。
#   标签: 能力,自我介绍
# - [03] 排位连跪被截图调侃 — 甩来战绩截图，她吐槽队友在梦游。
#   标签: 游戏,吐槽

# memory/2026/10/17/03-排位连跪被截图调侃.md
# 每个事件文件 = 全量记录（不是摘要！）：
# - 日期: 2026-10-17 00:31
# - 来源: 私聊
# - 标签: 游戏,吐槽
# - 一句话: 对方甩来一张战绩截图，她吐槽这队友是在梦游。
# 
# ## 全量记录
# 我: [图片]
# AI: 这战绩，你队友是闭着眼睛打的吧
# AI: 0/9/2，我甚至怀疑他在给对方送温暖
# 我: 我都快破防了
# AI: 别破防，你破防了他也不会突然会玩
# AI: 下一把带我，我至少不会送
```

**关键：目录=检索入口（便宜），正文=全量原样（贵但准）**

### 四个查记忆工具

| 工具 | 干啥 | 成本 |
|------|------|------|
| 查有哪几天 | 「我记忆里有哪些天」 | 几行字，极便宜 |
| 翻某天目录 | 只读标题+一句话 | 便宜 |
| 搜关键词 | 只在目录里搜 | 便宜 |
| 回放全量 | 调原话出来 | 贵，最后才用 |

### 踩过的5个坑

| 坑 | 教训 |
|----|------|
| **坑1：压缩丢细节** | 摘要丢语气 = 信息量0。不要压缩正文，要压缩的是「检索入口」 |
| **坑2：记忆塞prompt** | token×n + 缓存永远废。记忆拿出上下文，缓存立刻开始工作 |
| **坑3：让AI「猜」记忆** | 手里没细节又被要求回忆 → 合理脑补。**「记不清」是合法答案** |
| **坑4：一天一个文件** | 十件事塞一起 → 模型抓不住重点。**一件事一个文件** |
| **坑5：记忆和身份混放** | 性格会随记忆漂移（今天严肃明天玩梗）。事实记忆 vs 身份认知必须分开 |

### 边界

- 档案要有人维护（归档可能失败、分类可能错）
- 回放正文要花 token（先查目录再决定）
- 标题写得准不准决定检索质量（唯一真正需要「人」参与的地方）
- 不解决「理解」，只解决「别让它无米下锅」

### 真实数据

```
累计输入 1.69 亿 token
缓存命中率 97%
实际花费 约 10 元
如果不做缓存 约 169 元
差了 16 倍
```

## 二、高赞评论：识海节点式记忆（神奇海螺nb666）

> 赞 98 · Lv.22 · 湖南 · 2026-10-19

### 核心思路

> 我想发和你有点像，我做了一个**识海**，里面是大大小小的**节点**。
>
> - 根据 **时间久远**、**她自己认为的重要性** → 节点权重衰减
> - 节点间**互有关联**（关键词标签 + 语义连接）
> - 以**多个关键词**为标签
> - 她想到一个 → **触发相似的** → 她就会知道 → **像人的神经元一样**

### 计划加的功能

> 还没有开源，我在加 **时间、发散思维、走神、遗忘** 这些功能。

### 与主帖的对比

| 维度 | 主帖（华生忆梦） | 评论（神奇海螺） |
|------|------------------|------------------|
| 结构 | 五层分层（工作台→档案柜→录像） | **图结构**（节点互关联网） |
| 检索 | 目录先行，关键词搜标题 | **神经元触发**（相似节点自动激活） |
| 遗忘 | 滚动窗口易失，其他永久 | **时间+重要性加权衰减** |
| 身份 | 单独一层与事实分离 | 未提（可能也需分离） |
| 回放 | 四工具分层查（便宜→贵） | 触发后关联节点自动浮现 |

## 三、其他有价值评论

### 大白菜(●—●)（Lv.15 · 山东 · 12赞）

> 可以去了解一下 **RAG 知识库架构**，这个架构对于 AI 的长期记忆是很有效的。
>
> 大概逻辑：文本 → 向量化模型 → 向量+原始文本存储。语义相近的文本，向量化后的值就越接近。
>
> 查询时：问题 → 向量化 → 语义检索 → 取最相近的一组。
>
> 向量化模型很小，**完全可以本地部署**，实际查询不需要大模型。
> RAG 可以作为底层架构，然后根据需要往不同方向完善。

### 西木鹿亚（四川）

> RAG 已经是上个时代的产物了（23年的技术），它已经内化为了底层框架。
> **RAG → Graph → LLM Wiki**，就算是 RAG 也还有重排。

### 天-悬-星-河（北京）

> 感觉目前除了 RAG 没啥更好的办法，只能把对话切割存向量数据库，用的时候再查了。

### 快乐的小鲸鱼哦（广东 · 44赞）

> 看完就记住一句：**记不清也是合法答案**。

## 四、白泽对照：已有 vs 待补

### 白泽已有

| 模块 | 文件 | 对应 |
|------|------|------|
| memory.go | `agent/internal/memory/memory.go` | 基础记忆层 |
| graph.go | `agent/internal/memory/graph.go` | 节点图结构（→ 神奇海螺的识海） |
| hybrid.go | `agent/internal/memory/hybrid.go` | 混合记忆策略 |
| llmsum.go | `agent/internal/memory/llmsum.go` | LLM 摘要层 |
| notes.go | `agent/internal/memory/notes.go` | 笔记/事件层 |
| llm/embed.go | `agent/internal/llm/embed.go` | 向量化（→ 大白菜的 RAG） |
| kb/kb.go | `agent/internal/kb/kb.go` | 知识库（RAG 底层） |

### 待补（从两篇方案里抄）

| 缺口 | 来自 | 怎么做 |
|------|------|--------|
| **档案柜式全量归档** | 华生忆梦 第3层 | 每天定时把对话按事件粒度拆文件存，目录先行（白泽当前没做到"一件事一个文件"） |
| **身份/事实分离** | 华生忆梦 第4层 | persona（管理员写的稳定人设） vs memory（会增长的事实） → 已分离但边界模糊 |
| **原始录像层** | 华生忆梦 第5层 | 最底层永不删原始记录 → 白泽有 runs.db 但不是逐轮全量 |
| **神经元触发检索** | 神奇海螺 | 节点加权（时间衰减+重要性）+ 关键词标签 → 白泽有 graph.go 但缺权重和触发机制 |
| **查工具分层（便宜→贵）** | 华生忆梦 四个工具 | 先搜目录 → 再看摘要 → 最后回放全量 → 白泽 memory_tools.go 可以改成分层 |
| **归档自动化** | 华生忆梦 | 每天夜里定时跑归档任务 → 需要 cron 配合（白泽有 cron 模块） |
