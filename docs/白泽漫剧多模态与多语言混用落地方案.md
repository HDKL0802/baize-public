# 白泽 · 多模态漫剧 + 多语言定点混用落地方案
> 版本 v1.0 ｜ 日期 2026-10-24
> 依据你这轮敲定的硬性要求：
> ① 底层后端逻辑**保留 Go**，不推翻；
> ② 语言**定点混用**：Go 为主力，Rust 补底层生态，Python 少用（太重）；
> ③ 多模态最终验收标准 = **给一部小说，白泽自己做成「一集漫剧」**（含文生图/图生图/图生视频/文生视频）；
> ④ 记忆树 + 技能自动复盘闭环必须做；
> ⑤ 编码工具：主力换轻量 CLI 编码 Agent（推荐 Claw Code + DeepSeek V4.1），Trae CN 保留做编译/调试。

## 一、最终架构：多语言定点混用（Go 内核不动）
```
┌────────────────────────────────────────────────────────────┐
│  Go 内核（保留白泽全部现有逻辑，主力）                         │
│  调度 / 多用户 / 审批 / 频道 / 记忆星图 / 插件市场 /          │
│  记忆树(重写) / 技能系统+自动复盘闭环(补) / 任务引擎 / 后端API │
└──────────────┬─────────────────────────────────────────────┘
       Rust 层（只做生态强项，替换手搓底层）       Python 层（少用，仅子进程）
   ┌──────────────┴──────────────┐   ┌──────────┴──────────────┐
   │ 截图/键鼠/窗口 (xcap/enigo)  │   │ 图像/视频生成管线协调      │
   │ 本地 STT (whisper-rs)        │   │ (图生图/图生视频/文生视频   │
   │ 本地小模型推理 (llama.cpp)   │   │  —— 接模型 API，不在本地跑) │
   └──────────────▲──────────────┘   └──────────▲──────────────┘
                  进程隔离 + HTTP/进程间通信        │
   ┌──────────────┴──────────────────────────────────────────┐
   │  多模态 Provider 接入层（可插拔）                        │
   │  图片识别(已有) / 文生图 / 图生图 / 文生视频 / 图生视频     │
   └──────────────────────────────────────────────────────────┘
```
- **原则**：每个语言只做它生态最强、别的语言做不好的那部分；**三语言各写一套 = 维护地狱，禁止**。
- Go 保留：你写好的调度/多用户/审批/频道/记忆星图/插件市场全部不动。
- Rust 替换：手搓的截图/键鼠/窗口（治你"跨平台维护成本高"），加本地 STT 与本地小模型。
- Python：**只用做"生成管线协调"子进程**（因为图/视频模型的官方 SDK 多在 Python），本身不在本地跑大模型，控制它只拉最少依赖。

## 二、多模态能力清单（最终成品必须全有）
| 能力 | 现状 | 目标 | 实现方式 |
|---|---|---|---|
| 图片识别 | ✅ 已有（vision extract/translate、截图提问） | 保留 | Go 调多模态模型 API |
| **文生图** | ❌ | 必须有 | Provider 接入：AGNES 文生图 / 通义万相(Wan) / FLUX / Stable Diffusion |
| **图生图**（角色/风格迁移） | ❌ | 必须有 | 同上，传参考图；用于角色一致性 |
| **文生视频** | ❌ | 必须有 | Provider 接入：通义万相 Wan / 即梦 / 可灵 / Runway / Pika |
| **图生视频**（分镜图→动起来） | ❌ | 必须有 | Provider 接入：可灵 / 通义万相 / 即梦（漫剧主力） |
| 语音/字幕 | ✅ 有（voice TTS/STT、双语字幕） | 保留 | 漫剧配音/对白用 |

> **"让它自己生成"**：在 Go 内核加 Agent 工具 `image_gen` / `image_to_video` / `text_to_video`（危险？只读生成类，走权限闸门），白泽在对话里说"生成一个XX角色图"就能自己调 Provider。
> Provider 可插拔：新增"多模态 Provider"配置（和现有模型通道并列），AGNES 等填 Key 即用；模型名忘了没关系，接的时候看平台控制台填。

## 三、漫剧生成管线（验收标准：一部小说 → 一集漫剧）
```
小说文本
  ↓ ① 剧本/分镜（Go 调 LLM）—— 拆成一集、每集拆成 N 个镜头（场景+动作+对白+镜头提示）
  ↓ ② 角色卡（文生图，锁定主角形象）→ 图生图精修
  ↓ ③ 逐镜头生成场景图（文生图，提示词带入分镜+角色一致性参考）
  ↓ ④ 分镜图 → 图生视频（可灵/万相/即梦：图动起来，几秒/镜头）
  ↓ ⑤ 可选特效/转场（文生视频补充）
  ↓ ⑥ 配音/对白/字幕（voice TTS + 字幕；说话人分离暂不做，如实标注）
  ↓ ⑦ 合成一集（多镜头拼接 + 音画合成 → 输出成片）
```
**验收**：白泽收到整本小说 → 自动产出**第一集**成片（图/视频/音/字齐全），可作为"多模态+任务执行+记忆（记住角色/剧情/风格）"的综合测试标准。

## 六、风险与口径
- 图/视频生成**依赖模型 API 可用性**：没配 Provider 或配额不足时，Agent 如实报"未配置多模态 Provider"，绝不假装能生成（沿用白泽"不假装"铁律）。
- 视频生成慢、贵：默认每镜头 3–6 秒，可配置；漫剧先保证"能产出成片"，再谈画质。
- 记忆树/记忆星图并存：记忆树管长期人格经历，记忆星图管笔记知识图谱，两者不冲突。
