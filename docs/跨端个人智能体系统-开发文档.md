## 0. 决策基线（已确认）

1. **语言**：全项目统一用 Go 编写（含后端 Agent、桌面端、手机端），并首先完成 Go 全量重写，再在其上进行后续工作。
2. **许可**：全项目采用 **MIT 开源协议**。
3. **基座映射**："昆帕" 确认指 **QwenPaw**（通义 AgentScope 团队开源项目）。
4. **手机端通道**：**ADB 与无障碍服务两条通道都必须可用**（并行策略，非二选一），因为多数手机应用没有 CLI、只能走 UI 层。
5. **运行时底座**：采用 **PicoClaw**（Sipeed 出品，MIT、纯 Go、超轻量）作为 Go Agent 运行时底座。
6. **控制层现实**：PicoClaw 的浏览器自动化、Android/ADB 设备控制、桌面 GUI 自动化目前仅在 Roadmap（未交付），控制层需自研或以 Go 桥接 scrcpy / ADB / 无障碍 / 系统 API 实现。
7. **待办融合**：现有"秒哒(Miaoda) 手机端待办 App" **废弃原产品形态，以全新 Go UI 重写**，作为 Agent 的一个**插件**纳入系统，且以**双形态交付**：**(1) 插件版**——组件/模块直接内置进 Agent，作为手机端的一等公民模块运行；**(2) 独立 APP 版**——形态与原有秒哒 App 完全一致，可作为一个独立应用安装使用。两形态共享同一套 UI/领域逻辑/任务库核心，仅入口与打包方式不同。重写后保留四 tab 能力（待办/密码本/语音/设置），并新增第二种待办来源——Agent 待办，形成"双源待办/任务中心"。

## 1. 项目目标与定位

打造一套个人专属的跨端智能体：

- **后端 Agent（纯后端）**：单独部署在低配置 NAS 等设备上，Agent 直接在后端运行，只显示日志，负责"干活"和执行任务（例如前端下发"清除全部文件"任务后自动执行）。
- **桌面端（前端）**：连接后端，抓取本机信息并上报后端；对接 Windows 和 Linux。
- **手机端（前端）**：连接后端，抓取信息并上报；对无 CLI 的应用走 UI 界面控制，也支持 ADB / 无障碍通道；24 小时自动监听与回溯；密码插件的配合。
- **能力基调**："像真人一样"持续干活，任务可在手机与电脑间自动流转，接近鸿蒙小艺的体验，但本地优先、可自控。

## 2. 总体架构

三层结构（后端为中枢，桌面/手机为双翼）：

| 层 | 组件 | 职责 |
|----|------|------|
| 后端 | Agent（Go） | 对话/任务编排、长期记忆、模型路由、记忆管线、跨端调度、安全审批；只显示日志 |
| 桌面端 | Go 客户端 | 抓取活动窗口/进程/剪贴板并上报；按后端指令就地执行 |
| 手机端 | Android 客户端 | UI 自动化（scrcpy 风格 Copilot）、ADB/无障碍、24h 监听回溯、密码插件 |

数据/指令通过统一内部协议（HTTP/WebSocket 双通道，可选 gRPC）双向通信。

### 2.1 后端 Agent（NAS）
- 编排核心：prompt 构建、工具执行、重试/回退、回调、压缩、持久化。
- 记忆服务（Memory Tree + Obsidian 同步 + SQLite）。
- 模型路由（仅本地模型，删除云端与"OpenHerman 托管内网"）。
- 原生工具（浏览器、电脑控制、文件、编码、邮件、语音、记忆）。
- 任务队列与跨端调度、定时任务引擎、事件/钩子系统、技能/工具注册中心、安全审批、快照/回滚、备份恢复。
- 对外接口：REST/WebSocket；供桌面端、手机端、前端调用。

### 2.2 桌面端
- Windows：普通 CLI、cmd.exe、管理员 CMD（提权）共三种形态。
- Linux：普通 CLI。
- 悬浮球入口（豆包/昆帕风格）。
- 信息抓取上报 + 指令就地执行。

### 2.3 手机端
- 三通道执行：UI 自动化（scrcpy 服务端 + 坐标/无障碍点击）、ADB 桥接、无障碍服务（AccessibilityService）。
- 24 小时监听与回溯（前台服务 + 电池优化豁免 + OCR + 无障碍事件）。
- 密码插件（替换系统密码本，含账号/密码/验证码）。
- 集成待办模块：秒哒以 Go 重写为**双形态插件**（内置 Agent 的插件版 + 与原应用一致的独立 APP 版），承载用户待办/Agent 待办双源任务中心。

## 4. 四基座能力来源与取舍

### 4.1 PicoClaw（Go 运行时底座）
来源：Sipeed，MIT，纯 Go，26K+ Stars，footprint 常 <10–20MB。
- **采用**：agent core、CLI（agent/gateway/cron/mcp）、WebUI、终端执行 exec、19+ 消息通道、skill/ClawHub、MCP 扩展，作为目标 Go 骨架。
- **不依赖（Roadmap 未交付）**：浏览器自动化、Android/ADB 设备控制、桌面 GUI 自动化。控制层由我们自研 + 桥接 scrcpy/ADB/无障碍/系统 API。
- **注意**：PicoClaw 官方标注"早期快速开发、v1.0 前不建议生产"，须锁定版本（如 v0.3.x）并以接口层隔离封装。

### 4.2 OpenHuman（记忆参考；不复制源码）
来源：TinyHumans AI，GPL-3.0，Rust+TS（Tauri、SQLite）。中文社区 openhuman.org.cn。
- **保留思路（独立实现为 Go）**：Memory Tree 长期记忆树、记忆管线/AgentMemory 后端、Auto-fetch 自动抓取、模型路由（删云端）、Token 压缩（TokenJuice）思路、潜意识循环（24h 后台）、外部记忆（Obsidian/Wiki/邮箱）、原生工具（浏览器/电脑控制/编码/语音/会议）。
- **废弃**：其 UI 界面、云端模型、托管内网、"远程核心/远程后端"（无独立后端依据，用自研 Go 后端承担远程后端角色）、国外不可访问集成（X/Twitter、Danger 等）。

### 4.3 昆帕 QwenPaw（界面与编排，Apache-2.0）
来源：通义 AgentScope 团队，Python+React+FastAPI。官网 qwenpaw.agentscope.io。
- **保留**：整体界面/控制台外部界面、魔法命令、定时任务（替换 OpenHuman 心跳）、多智能体（替换 OpenHuman 多 Agent 协作）、Skill 与 MCP、上下文管理、工作目录、安全系统、备份恢复、后端、电脑前端（手机不用其前端）、插件系统、独立浏览器、视频创作平台 Creator。
- **频道保留**：飞书、Discord、QQ OneBot V11、个人微信、腾讯元宝、小易、Either BOT。
- **频道删除**：企业微信，以及其他不在保留清单内的频道。
- **说明**：独有浏览器保留；自带浏览器可用；电脑操作结合 OpenHuman/Qwen 取优。

### 4.4 Hermes Agent（检查点/钩子增强，MIT）
来源：Nous Research，Python 3.11。中文文档 hermes-agent.nousresearch.com/docs/zh-Hans/。
- **保留**：检查点与回滚、技能系统与工具系统（含创建/使用技能的精髓）、代码执行、目标（/goal）、多代理协作、事件钩子与 Plugin hooks、上下文压缩与缓存、上下文引用（@注入）、开发者"程序化集成"与"拓展"（插件发现）。
- **废弃**：记忆系统（用 OpenHuman 记忆）、前端页面、消息网关（用昆帕频道/网关）、人格/SOUL（部分由上下文引用替代）。
- **语义映射**："循环工程"→其 Agent 循环/Ralph loop；"P/hook"→事件钩子/插件钩子；"三种协议"→程序化集成入口（CLI/API Server 等）。

## 6. 后端 Agent 需求

### 6.1 核心模块
- **Agent 运行时底座**：基于 PicoClaw(Go)。以 agent core/CLI/Gateway/cron/MCP/skills/WebUI 为骨架重建。
- **Agent 编排核心**：借鉴 Hermes run_agent 主循环（provider→prompt→工具→重试→回退→回调→压缩→持久化）。
- **记忆服务**：Memory Tree + SQLite + Obsidian 兼容 .md（独立 Go 实现，勿抄 GPL 源码）。
- **模型路由**：仅本地模型（Ollama/vLLM/Llama.cpp），按任务类型/成本/隐私路由；不接云端。
- **工具运行时**：浏览器、电脑控制、文件、编码、邮件(IMAP IDLE+SMTP)、语音 STT/TTS、Obsidian/照片。
- **跨端调度**：任务队列 + 设备注册表 + 能力探测；把任务路由到具备能力的端。
- **定时任务引擎**：Cron（昆帕机制，替换 OpenHuman 心跳）。
- **事件/钩子系统**：生命周期钩子、日志/告警/webhook/指标。
- **技能/工具注册中心**：Skill Pool + Workspace Skills + MCP 热插拔 + agentskills.io 兼容。
- **安全与审批**：工具防护、文件防护；删除/支付/发布/发消息/改权限/正式提交类需人工确认。
- **快照/回滚**：变更前自动快照，失败回滚。
- **备份/恢复**：完整/自定义备份、导出导入、安全点。
- **接口**：HTTP/WebSocket 双通道（约定消息：task_id、payload、status、device_id、回执）。

### 6.2 后端行为要求
- 只显示日志，运行于低配 NAS。
- 低配置约束：本地小模型 + 量化，重活分发外部算力；不把超大模型塞同一 NAS。
- 统一消息协议，多语言接口；以 `.proto`（gRPC/Protobuf）生成 Go 与 Android 桩，保持契约一致。

## 7. 桌面端需求

### 7.1 Windows（三种执行形态）
- LINUX 普通 CLI：覆盖绝大多数自动化任务。
- Windows CLI：普通权限命令行。
- Windows CMD：经 cmd.exe 解释器执行批处理/系统命令。
- Windows 管理员 CMD：提权执行（UAC/service token），仅授权任务使用，预留审计日志。

### 7.2 信息抓取与上报
- 活动窗口、前台进程、剪贴板、近期打开文件、磁盘/网络状态。要求：仅采集已授权白名单（应用/路径）、上传走加密通道、默认关闭、可一键停采、敏感内容默认脱敏。

### 7.3 悬浮球
- 类豆包/昆帕小悬浮窗：快捷唤起、显示任务状态、一键停止采集。
- PicoClaw 桌面定位：exec 终端执行+cron+skill 充当桌面本地 Go 执行层（覆盖 CLI/普通 CMD）；提权与抓取由我们的 Windows 客户端封装系统 API。

## 8. 手机端需求

### 8.1 三通道执行（并行，两主为重）
1. **UI 自动化（scrcpy 风格 Copilot）**：复用 scrcpy 屏幕镜像与服务端监控服务（坐标/无障碍点击）。上层 Go Agent 驱动"看一屏→判断→点击/输入→断言"闭环，支持自然语言转操作序列。这是无 CLI 应用（抖音、系统设置、各类 App）的主要手段。
2. **ADB 桥接**：可给 ADB 权限时优先 ADB（tap/text/swipe、UI dump、截屏、包管理、控件定位），速度与确定性更高。
3. **无障碍服务(AccessibilityService)**：无 ADB/无 root 时用无障碍服务映射全局状态（窗口、焦点、文本、点击、输入），是"24h 监听 + 无障碍操作"的常驻通道。

**要求（已确认）**：ADB 与无障碍两条通道都必须可用；策略为并行——可给 ADB 权限优先 ADB，否则回落无障碍；对内统一成一套"看屏→决策→点击/输入"的 UI 自动化能力，供 scrcpy 风格 Copilot 复用。

### 8.2 24 小时监听与回溯
- 持续运行：前台服务 + 电池优化豁免，手机电脑开着即常驻。
- 事件识别：本地 OCR 读屏 + 无障碍事件判断当前界面；对"打开 App→注册→输入账号密码"流程做分段还原。
- 回溯记录：把"干了什么、在哪做、输入了什么"按时间轴折叠成记忆条目上报，落入 Memory Tree；支持事后查询。

### 8.3 密码插件与验证码保存
- 实现为键盘输入法(IME) 或无障碍 autofill 桥，读取本地加密密码库并按需填入目标 App。
- 验证码（短信/邮件捞取）同样入库，支持自动填充。
- 密码库与记忆分离加密存储（AES-GCM + Argon2），密码明文不出设备本地加密层。
- 对接待办 App 的"密码本"tab（MD 智能提取、浏览器导入）。

### 8.4 手机端还需
- 与后端长连接、心跳、任务接收与回执。
- 常驻后台保活、权限自管理（无障碍/屏幕录制/autofill 回调到设置页）。
- 集成秒哒待办 App（见第 9 节）。

## 9. 待办与任务中心（双源待办）需求

### 9.1 定义与交付形态
把现有"秒哒(Miaoda) 手机单端待办 App" **以 Go UI 全量重写**，作为 Agent 的插件，并以**双形态**交付：

| 形态 | 说明 | 入口/打包 |
|------|------|-----------|
| **插件版** | 直接内置进 Agent 手机端，作为一等公民模块运行 | 由 Agent 主进程拉起、加载其 UI 与逻辑，数据进 Agent 统一任务库 |
| **独立 APP 版** | 形态与原有秒哒 App 完全一致，可独立安装使用 | 独立 APK，自带入口，可与 Agent/后端单机直连 |

两形态**共享同一套核心**：UI 组件库、领域逻辑（待办/密码/语音/设置模块）、任务库 store、加密层；仅在外壳（宿主容器）与打包产物上做区分，避免重复维护两份代码。独立 APP 版可作为 Agent 的"瘦客户端"，向配置/未引入 Agent 的场景开放；插件版则是 Agent 完整能力内的内嵌模块。

重写后保留四 tab（待办/密码本/语音/设置）全部能力，并新增第二种待办来源——**Agent 待办**，构成"双源待办/任务中心"。

### 9.2 双来源
- **用户待办**：在 App 里创建（界面/快速回车/语音"加一个明天复习待办"），字段含类别、优先级、时间、备注、依赖前置。
- **Agent 待办**：Agent 主动产生的任务（自拟、长期目标分解、对话意图、监听事件派生、定时任务派生），同样有类别/优先级/时间/依赖前置，且带执行授权状态。

两者进同一个统一任务库 store，按键分开、属主字段区分 user / agent；用户可一键对某条 Agent 待办关闭/改期/授权执行。

### 9.3 四个 tab 能力到重写后的映射（秒哒四 tab → Agent 插件模块）
| App tab | 现有能力 | 处置 |
|---------|----------|------|
| 待办 | 日程/闲暇双视图、AI排期、快速加待办、分类/优先级/时间/依赖前置 | 用户侧待办客户端；AI排期改由 Agent 承接（给方案、你确认）；依赖前置供调度器判序 |
| 密码本 | 取代系统密码库、MD 智能提取、浏览器导入、凭据入库 | = 密码插件，与本地加密凭据库打通 |
| 语音助手 | 1×1/1×2 语音微件、自然语言加待办/存密码、自动解析日期 | 语音交互入口，意图解析走后端 |
| 设置 | DeepSeek/Claude/OpenAI 接口、Markdown 导出导入(兼容 Obsidian)、通知/高精度闹钟 | 模型接口集中到后端路由；MD 对接 Obsidian；闹钟并入定时任务引擎 |

### 9.4 任务流转边界
- 只有**授权的 Agent 待办**会被后端自行调度执行。
- 用户待办默认"只记录不擅自动"：需要转交 Agent 执行时显式授权，或开全局"待办自动执行"开关。

## 10. 跨端任务流转

- 统一任务形态（task_id、payload、目标设备、status、回执）。
- 后端调度器按"目标设备可达性 + 所需工具"决策：
  - 手机布置 → 需电脑能力 → 转发桌面执行 → 回传结果；
  - 电脑布置 → 需手机能力 → 转发手机（UI 自动化/ADB/无障碍）→ 回传结果；
  - 需查资料/记忆 → 工具 + Memory Tree。
- 结果统一落记忆并通知。
- 幂等与确认闸门：删除（尤其"清除全部文件"类）、支付、发布、发消息、改权限、正式提交等强制人工确认。

## 11. 语音交互

- 复用 OpenHuman 语音思路（Whisper-rs 本地 STT + Piper/ElevenLabs TTS）。
- 桌面/手机提供语音输入，自然语言转指令：加待办、存密码、发起任务、查询记忆。
- 移植秒哒 App 的"语音助手"微件（1×1/1×2）作为手机端入口。
- 语音涉及系统权限（麦克风/无障碍）需在设置页授权。

## 12. 安全、隐私与合规需求

- 数据在静：AES-GCM + Argon2 加密记忆库与凭据库；密码明文仅驻设备内存。
- 传输：端与后端全链路 TLS（mTLS 双向证书）；NAS 对内网；外部走 VPN/受限网关。
- 最小权限：采集按应用/路径/界面白名单；授权外不监听，剪贴板默认脱敏。
- 危险操作闸门：删除/支付/发布/发消息/改权限/正式提交类强制人工确认。
- 口令与验证码：绝不送云端模型，仅本地密码插件可用，可一键清除。
- 合规：Android 需要无障碍/屏幕录制/autofill 权限；对"持续性屏幕监控 + 凭据采集"做隐私说明并保留用户开关。
- 开发早期先写"采集边界与授权清单"。

## 13. 页面清单总览（含直接描述）

> 说明：下文每一页给出"用途 / 主要元素 / 交互"。页面分四块：手机端、桌面端、后端、待办双源扩展。
> A/D 组（待办相关）页面由秒哒 Go 重写的"待办任务中心"统一承载，**插件版与独立 APP 版共用同一套页面实现**（仅外壳宿主不同）。

### A. 手机端页面

**A1. 待办首页（双源视图）**
- 用途：待办/任务中心主界面，同时呈现"我的待办"与"Agent 待办"两类，并可做日程（按时间）与闲暇（按优先级/类型）两种排布。
- 主要元素：顶部 tab/分段（我的待办 / Agent 待办）；视图切换（日程排期⇄闲暇待办）；AI 排期建议条；"快速记录今日排期任务"输入框（回车添加）；任务卡片（标题、类别标签、优先级、时间、备注、依赖前置标记）；底栏导航（待办/密码本/语音助手/设置）。
- 交互：左右滑动切换日程/闲暇视图；点卡片进详情；长按卡片操作（编辑/删除/指派/授权 Agent 执行）；Agent 待办卡片显示"待授权/执行中/已完成"状态并可一键授权或改期；快速输入框回车入待办。

**A2. 待办详情/编辑页**
- 用途：查看/新增/编辑单条待办。
- 主要元素：标题；类别（工作/创作/生活等）；优先级（高优/中/低）；日期时间（可选提醒）；备注；依赖前置（选择其他待办）；属主（user/agent，Agent 待办可切换/展示）；作者与创建时间。
- 交互：表单填写后保存；Agent 待办可在此授权执行或转派设备；删除需二步确认。

**A3. AI 排期页**
- 用途：查看 Agent 对待办的自动排期建议，决定是否采纳。
- 主要元素：建议时间轴（按依赖前置排序）；每条待办的建议时间与理由；一键采纳/修改/忽略。
- 交互：采纳后写入日程视图；修改后重新生成；可设置排期策略（学习周内学习任务优先等）。

**A4. 密码本页**
- 用途：自用密码本，取代系统密码库；承载账号/密码/验证码/备注。
- 主要元素：凭据列表（标题、账号、掩码密码、关联 URL、备注、来源标记[用户录入/MD 导入/Agent 捕获]）；搜索；"导入（MD/浏览器）"与"新建"。
- 交互：点条目查看/复制/编辑；复制密码；新增凭据；数据打主要本地加密，明文不落盘可读。

**A5. 语音助手页**
- 用途：语音快速加待办、存密码、发起指令。
- 主要元素：1×1 语音球 / 1×2 语音微条；按住说话/轻按说话；常用指令快捷标签（"加一个明天复习待办""加一个GitHub密码…"）；识别结果预览与确认。
- 交互：按住说话→识别→预览解析出的待办/密码→确认入库；可点按微条常驻桌面的快捷入口。

**A6. 设置页**
- 用途：模型接口、数据、通知、权限、系统级集成配置。
- 主要元素：模型配置（DeepSeek/AGES/Anthropic/OpenAI 模板、BaseURL、API Key、Model）；Markdown 数据中心（导出/导入 Obsidian 兼容 MD）；通知与闹钟（横幅/锁屏/免打扰/高精度闹钟/触觉反馈）；系统权限跳转（无障碍、屏幕录制、autofill、麦克风）；数据管理与恢复（恢复初始示例/清空）。
- 交互：选择模板并填入接口信息→"测试接口连通性"→保存；一键导出/导入 MD；权限项点击跳系统原生设置页。

**A7. 配对/登录页**
- 用途：手机端与后端 Agent 建立受信连接。
- 主要元素：后端地址与配对码输入；已配对设备列表；二维码。
- 交互：扫码或输码配对；显示连接状态。

**A8. Agent 面板页（手机）**
- 用途：查看 Agent 待办、执行状态、历史与授权。
- 主要元素：Agent 待办列表（含来源[自拟/目标分解/监听/定时]）；执行状态；授权开关；跨端流转轨迹（从手机转到电脑等）。
- 交互：授权/拒绝 Agent 待办；查看某任务的执行日志（只读）；暂停/恢复 Agent 自主执行。

### B. 桌面端页面

**B1. 悬浮球**
- 用途：常驻桌面的轻量入口（豆包/昆帕风格），显示运行/任务状态，快捷唤起控制面板或语音输入。
- 主要元素：圆形悬浮球；状态圆点（空闲/忙碌/待确认）；菜单（打开控制面板、一键停止采集、退出）。
- 交互：拖拽移动；单击展开菜单/唤起；长按进入设置。

**B2. 系统托盘**
- 用途：Windows/Linux 托盘图标，管理后台进程与状态。
- 主要元素：托盘图标、右键菜单（状态、打开面板、暂停监听、退出）。
- 交互：单双击打开面板；右键菜单操作。

**B3. 桌面控制面板（Web 轻量页）**
- 用途：查看本机抓取的信息、接收/执行的后端任务、日志。
- 主要元素：当前活动窗口；前台进程；任务列表（含 CLI/CMD/管理员CMD 三形态执行记录）；执行结果回执；日志流。
- 交互：查看任务详情；对"管理员 CMD"任务确认提权执行；一键停止采集。

**B4. 桌面授权/审批弹窗**
- 用途：危险操作（删除、提权、发送）执行前的人工确认。
- 主要元素：操作描述、目标、影响范围、建议；确认/拒绝按钮。
- 交互：弹窗置顶等待用户确认；超时默认拒绝并记录。

### C. 后端页面

**C1. 后端日志/控制台页**
- 用途：后端 Agent 只显示日志，供排障与状态查看。
- 主要元素：滚动日志流（按级别过滤）；运行状态卡；设备在线列表；任务队列概览。
- 交互：级别过滤（debug/info/warn/error）；暂停日志；设备详情跳转。

**C2. 核心配置页**
- 用途：后端级配置。
- 主要元素：模型路由（本地模型列表/成本/隐私）；记忆设置（抓取频率/存储位置/摘要质量）；工作目录；定时任务；备份入口；网关配置。
- 交互：保存后生效；改关键项需管理员权限。

**C3. 任务队列/调度页**
- 用途：查看统一任务库与跨端调度。
- 主要元素：任务列表（属主[user/agent]、状态、目标设备、回执）；跨端流转轨迹。
- 交互：筛选、重试、取消任务；查看单任务执行轨迹。

**C4. 审批中心页**
- 用途：后端统一承接各端危险操作确认。
- 主要元素：待审批队列（类型、来源、描述、影响、决策按钮）。
- 交互：批准/拒绝；审批记录可追溯；可设自动审批白名单。

### D. 待办双源扩展页面

**D1. 双源切换与筛选**
- 用途：在待办首页一键区分"我的待办 / Agent 待办"。
- 主要元素：顶部分段控件；来源筛选标签；数量徽标。
- 交互：切换视图只看某一类；混排时用标签区分属主。

**D2. Agent 待办派生/授权页**
- 用途：展示 Agent 为何产生这条待办、是否要执行。
- 主要元素：原因/来源说明（派生链：目标→分解→任务）；预计耗资源；建议设备；授权按钮。
- 交互：查看派生链；一键授权执行（可转派设备）；拒绝并给出理由（供 Agent 学习）。

**D3. 待办 Markdown 导入/导出页**
- 用途：与 Obsidian 等外部系统互通待办/密码。
- 主要元素：导出按钮；导入文件选择；格式预览与冲突提示。
- 交互：导出为标准 MD；导入时校验结构与去重；冲突时提示选择。
