# 改造方案：白泽手机端「后端直控 + 虚拟屏 + 代码化 UI」

> 版本：v0.1（方案稿）｜ 日期：2026-11-21 ｜ 依据：[[评估-抖音晨钟酱AI手机控制方案]] + docs/白泽功能切分与本地控制方案.md + docs/白泽本地控制实施计划.md
> 性质：方案，未动工。本轮不改任何代码、不升版本号。

## 0. 目标形态（用户 m00038 拍板）
手机端由后端服务器直接控制干活；控制链路走虚拟屏——虚拟屏必须有，否则控制时打扰用户本人用机（刷视频等）。决策输入从「截图 + OCR」改为「UI 代码（界面树）」，截图/OCR 仅兜底。

## 1. 架构（三层，复用已有设备中枢）
- 执行层（手机端，新增）：虚拟屏常驻 Service（应用画到虚拟屏）+ UI 树采集（UIAutomator dump / 无障碍）+ 动作执行（tap/swipe/input/key/launch，风格按现有 shared/proto 白名单）。
- 中枢层（后端，已有）：/ws/device 长连接 + hub 派任务 + 审批闸门（docs 事实），本方案只新增动作类型，不改协议骨架。
- 决策层（云端模型，已有选型）：autoglm-phone / glm-4.6v；observe 输入由「截图」改为「UI 树 JSON」，截图作兜底与审计留存。

## 2. 任务拆解（R 编号，接现有 P0–P4 之后）
| ID | 任务 | 要点 | 验收 |
|---|---|---|---|
| R0 | 取证补齐 | 用户开新一轮看片，回填评估 §6（虚拟屏形态/启动应用细节） | 评估文档 §6 清空 |
| R1 | 虚拟屏通道 | Android VirtualDisplay/Presentation 或云手机/模拟器路线三选一（给对比表）；屏幕来源切到虚拟屏 | 控制期间用户真实屏零干扰（实测截图对比） |
| R2 | UI 树通道 | UIAutomator dump XML → 归一化 JSON（节点/文本/边界/可点）；0–1 坐标归一化沿用 wm size 思路 | 目标 App 界面树完整率 ≥95%（样本 10 页） |
| R3 | 决策回路改造 | observe 返回 UI 树（截图并存审计）；动作建议走树节点 id，不走像素坐标 | 同任务平均决策轮数 ≤ OCR 路线一半（对照实测） |
| R4 | 启动应用原语 | 按 [[收录-应用启动思路]] 设计 android.launch（包名/路由）；启动清单收录进本库 | 5 个目标 App 一键冷启动 |
| R5 | 安全与接管 | 复用 T1.5 Take_over；支付/验证码/锁屏必人工；canvas 自绘页自动回落截图+OCR | 敏感场景 100% 触发接管，不硬闯 |
| R6 | 速度验收 | 长任务（≥5 分钟级）端到端时长对比：OCR 路线 vs 代码路线 | 代码路线快 ≥1 倍（对齐公开评论量级预期，实测为准） |

## 3. 风险与兜底（诚实清单）
| 风险 | 来源 | 兜底 |
|---|---|---|
| canvas 自绘/游戏页无 UI 树 | 分享页公开评论（二手） | 回落截图 + 视觉/OCR（R3/R5） |
| 控制时手机被占线 | 同上 | 虚拟屏方案本身即解法（R1）；占线负面转验收项 |
| FLAG_SECURE 页黑屏 | docs/白泽功能切分与本地控制方案.md §2.1 | 标记 secure_page 回执，人工接管 |
| 无障碍权限门槛 | 实施计划 P3 | 引导页 + ADB 路线保留回退 |
| 执行时长仍久 | 同上评论 | R6 量化，不达标不推广 |

## 4. 与现有计划关系
- 不推翻 P0–P4：P1 手机竖切照跑，本方案在其上叠加「虚拟屏 + UI 树」通道；P3 无障碍增强因此提前。
- 不并任何第三方代码（AGPL 与 MIT 冲突，已有定论）；只对齐思路。

## 5. 版本纪律
本轮仅文档与知识库，未动代码、未升版本号；实施时按仓库纪律递增补丁位并同步三处（AndroidManifest.xml + build.ps1 + index.html）。
